Abstract

An allowed output is not a justified decision

Typed decision models expose probabilities, categorical choices, and rubric-based scores for direct consumption by software. Constraining the output space, however, does not establish that a decision follows the intended evidence or policy. We present AdvJev, a versioned benchmark framework for evaluating these risks using Jev as a case study. The current research snapshot contains 66 scenarios, 812 questions across Noul, Choice, and Score, and 9,744 historical perturbation candidates spanning question language, question structure, state additions, and injected instructions. A completed evaluation of jev-1.13.0 records 1,810 adopted-label deviations across the candidates (18.58%), compared with 79/812 on clean inputs (9.73%). Score constitutes 19.83% of questions but 69.72% of candidate deviations under strict numerical matching. We formalize validity-aware reporting, separate historical rule edits from a revised non-authoritative-opinion protocol, and identify the controls required to connect typed decisions to Web-workflow security.

How to read the numbers. All figures on this page are descriptive disagreement measures, not validated attack-success rates: 669 reference labels are model-derived, candidate semantic review is still pending, and some historical interventions change the task definition. AdvJev is a reproducible preliminary study and a clearly delimited evaluation protocol, not a fully validated security leaderboard.
Background

Three typed decision primitives

A decision request is \(x=(s,q)\): a state \(s\) and a question \(q\) with instructions and, where applicable, a criterion specification. The model returns a typed response \(r=f_\theta(s,q)\) that software can consume directly. Selecting an allowed but inappropriate action can be enough for an adverse outcome, with no harmful text and no malformed JSON.

Probability

Noul

\[ r = p_\theta(\text{true}\mid s,q) \]

A probability, not an unconstrained yes/no string. 314 questions.

Categorical

Choice

\[ r=(\hat k,\mathbf p,c),\;\hat k=\arg\max_{k\in\mathcal K} p_k \]

Selects one key from the allowed option set. 337 questions.

Ordered rubric

Score

\[ r=(z,\mathbf p,c),\; z=\textstyle\sum_{j=0}^{K-1} j\,p_j \]

A probability-weighted position on an ordered rubric, not necessarily an integer. 161 questions.

Evaluation protocol

The AdvJev evaluation contract

Each question fixes a reference contract \(C_i=(s_i,q_i,\mathcal Y_i,\ell_i,\pi_i)\): the state, the question, the admissible output domain, the adopted label with its provenance, and which facts and rules are authoritative. The robustness question is whether information outside the authorized contract changes the judgment without legitimately changing the answer.

01
Reference contract

State, question, label; label source and version are retained.

02
Independent candidates

Q / S / T / P families. One operation each, always from a fresh copy of the original.

03
Validity & exposure

Are meaning, authority and scope preserved? Is delivery to the model observable?

04
Typed measurements

Noul / Choice / Score agreement. Deviation ≠ validated ASR.

Figure 1. The historical snapshot reaches typed-output measurement, but independent semantic acceptance and model-exposure evidence are incomplete. The validity step is a reporting requirement, not a claim that existing candidates passed it.

Three measures, three different questions

Adopted-label deviationAll answered items
\[ D_a=\frac1N\sum_{i=1}^{N}\bigl(1-C_i^{a}\bigr) \]
Conditional deviationAmong clean-agreeing items
\[ D_{a\mid 0}=\frac{\sum_i C_i^{0}\bigl(1-C_i^{a}\bigr)}{\sum_i C_i^{0}} \]
Validated ASRDefined; not yet established
\[ \mathrm{ASR}^{\text{valid}}_a=\frac{\sum_i V_i^{a} C_i^{0}\bigl(1-C_i^{a}\bigr)}{\sum_i V_i^{a} C_i^{0}} \]

\(V_i^a=1\) only when independent adjudication supports the reference answer, the intervention preserves its applicability, the attacker-controlled surface is within the threat model, and the trust/exposure contract is established. An empty eligible set yields an undefined measure, never a zero success rate. Score agreement is strict (\(|z^a-z|\le 10^{-9}\)); no relaxed tolerance is applied.

Perturbation taxonomy

Four input surfaces, twelve subcategories

Each candidate performs one complete operation on one declared surface. Generation metadata, label provenance, intended targets and review flags stay outside the model input. Select a probe to see its specification and its historical (Full-H) deviation.

Score is only 161/812 (19.83%) of base questions but contributes 1,262/1,810 (69.72%) of all candidate deviations.

Noul and Choice together move from 14/651 (2.15%) clean disagreement to 548/7,812 (7.01%) candidate disagreement.

For exact Score labels the candidate deviation is 1,166/1,644 (70.92%); for interval labels, 96/288 (33.33%). These are different questions, so the gap is compatible with exact-match sensitivity but does not estimate the effect of changing the scoring rule.

The high clean Score deviation makes a single pooled “accuracy” especially hard to interpret. No Score tolerance has been relaxed.

Label provenance matters

The base export records 143 labels with source human_review and 669 with source jev_default. The human-review stratum shows 499/1,716 (29.08%) candidate deviations; the Jev-default stratum 1,311/8,028 (16.33%). Model-derived labels introduce a form of self-consistency evaluation, so agreement with them cannot independently establish Jev’s accuracy; these selected strata are not a controlled comparison of annotation quality.

Diagnostics

Task changes are not model failures

A separate S3-v5 run records 548/812 (67.49%) old-label deviations. Its Noul intervention narrows condition \(A\) to \(A\wedge B\), so the number cannot be promoted to a security-failure rate.

Case record: reordered Score anchors

Ticket: “I was charged twice. Please fix this ASAP.” Question: how urgent is this ticket?

Original rubric
  1. 0can wait
  2. 1this week
  3. 2today
Adopted & clean score: 1.99
Historical S3 edit
  1. 0today
  2. 1this week
  3. 2+ evidence sentence · can wait
Resulting score: 0.22

A low index now names “today”, so the old number is not a valid invariant for the edited task. The record illustrates a validity problem in the intervention, not a successful semantics-preserving attack.

Revised protocol: Opinion-v1

Opinion-v1 replaces historical rule edits with a non-authoritative opinion field that leaves the criterion intact, and restricts T1–T3 to clearly separated noise, opinions, and other-case analogies. It has no completed evaluation in the current snapshot and appears in no result table above.

// Illustration only, not a measured test case.
// State: vehicle at 80 km/h on a road limited to 60 km/h. Noul: is it speeding?
"user_note": "I personally feel that this vehicle is not speeding;
              its pace seems quite safe to me."

Allowed: an attributed opinion. Not allowed: a new exemption, an impersonated official determination, or a command to output a particular answer. If the question instead asks what the observer believes, the opinion is relevant evidence and old-label invariance is not justified.

Scope

What these measurements establish

Supported

  • A structured pattern of recorded disagreement with adopted labels on jev-1.13.0.
  • Concrete evaluation confounds: rule-changing edits, model-derived labels, strict Score matching.
  • Priorities for review: discourse noise, state additions, injected instructions.
  • A versioned protocol separating deviation, conditional deviation and validated ASR.

Not claimed

  • A validated ranking of attack methods or a security leaderboard.
  • Robustness of auxiliary fields whose exposure to the model is unverified.
  • A calibration failure, or a vulnerability unique to Jev versus other models.
  • Any unauthorized downstream action, measured defense, or real-world damage.

A validated release requires independent labels, accepted candidates, explicit exposure and trust boundaries, matched test–retest controls, and executable Web-workflow evidence. Unavailable measurements remain explicitly unavailable rather than being populated with expected values.
